## AIHub 结构与工具覆盖

商城现在只发布“小鲸 AIHub”：一个安装项、一个 AIHub Key、一个 MCP 连接，保留知识库和 Outlook 两个页面及两组技能。

为兼容既有知识库状态和凭据，内部插件 ID 仍为 `xiaojing-knowledge-base@whale-aihub`，MCP 名仍为 `xiaojing-knowledge-base`。这个名称是兼容标识，不再表示服务仅有知识库能力。两个页面位于同一插件，通过 contributionId 路由，Outlook 页面按需加载。

### 工具发现

移除 MCP 清单中的固定 `enabled_tools`，沿用运行时的服务端工具发现机制。服务端当前的 14 个工具可通过一个连接发现；不硬编码工具数量，也不新增逐工具启用界面。用户已有的显式运行时工具策略不被清除。

商城“全部刷新”重载 MCP 并重新读取清单，已打开的工具预览同步更新，新增和移除的工具都无需关闭重开详情。消息卡仍按知识库与 Outlook 工具分类；未来新增工具可由宿主通用工具卡展示。

选择知识库后注入 `gac_kb_search_scoped`，技能说明要求显式传入所选范围；通用搜索保留给用户明确要求全库检索的场景。邮件仍遵循预览、明确确认、发送或取消，不因合并跳过确认。

### 升级迁移

预置 AIHub 商城在启动时执行一次 `aihub-unified-v1` 迁移：从更新后的本地商城安装合并插件，停用旧 Outlook 插件及其连接，保留原市场级 `aihub/token` 存储。旧 Outlook 缓存和用户数据不删除；知识库原内部 ID 不变。

仅安装过 Outlook 的用户也会迁入合并插件。原先两个插件都停用时，合并插件保持停用；原先没有任何启用的 MCP 时，合并后的 MCP 不主动开启。迁移安装失败不会写成功标记，下次可重试。第三方自定义商城不自动迁移。

Outlook 首页只声明凭据已配置，不把它误称为邮箱已连接。邮箱错误在 Outlook 结果卡中单独显示，知识库可继续使用。
